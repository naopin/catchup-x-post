# 記事・運用要件（追記用）

新しい要件はこのファイルまたは `collect.md` / `write.md` / `publish.md` に追記する。コードのプロンプトと矛盾する場合はコードを正本とし、ここを更新する。

## 記事フォーマット（output/*.txt）

```text
トピック: {トピック名}

【概要】
{3〜5文}

【メリット・デメリット】
メリット:
・{2〜4項目}
デメリット:
・{2〜4項目}

【解説】
{背景・仕組み・他技術との違い}

【活用事例】
{1行1事例。先頭の「・」は任意}

参考: {X投稿URL}

【X投稿文案】（内容のみ・280字以内）
{280字以内。末尾にURL・ハッシュタグ可}
```

## 収集

- 直近7日以内の X 投稿のみ
- 英語・日本語横断
- エンジニア向け技術（言語/AI/インフラ/Web）
- トピックは API が自動選定（ユーザー指定なし）

## 解説

- 検索結果の転載ではなく編集記事として書く
- 「Xで話題」「Twitter」など情報源が X とわかる表現は避ける
- 【まとめ】セクションは不要

## 投稿

- 既定は dry-run（X 未投稿）
- 本番投稿は人が `output/*.txt` を確認した後のみ
- ハッシュタグ: #エンジニア #技術 から最大2個（コード側プロンプト）

## topics_history 行フォーマット

```text
選んだトピック: {トピック} ({タイトル}) https://x.com/.../status/...
```

## バッチ生成

- `ARTICLE_COUNT` または `go run ./cmd/post -count=N`（最大20）
- 1件あたり catchup-news を1回呼び、履歴更新後に次のネタへ
- 複数件時のファイル名: `output/YYYYMMDDHHMM_01.txt` …（1件のみのときは従来どおり `YYYYMMDDHHMM.txt`）
